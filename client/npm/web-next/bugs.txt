## 🔴 CRITICAL BUGS

### 1. **Indexing: 400 Bad Request on Source Scan**
**Status**: PARTIALLY FIXED (authentication added, but may still have issues)
**Files**: 
- `app/api/sources/scan/[sourceId]/route.ts` (proxy route)
- `hooks/useDashboard.ts` (useScanSource mutation)
- `client/web/main.py` (legacy scan_source endpoint)

**Description**: 
When clicking "Scan" on a source in the dashboard, the request to the ingest sidecar returns 400 Bad Request. The proxy route now includes authentication headers, but there may still be additional validation requirements from the Python sidecar.

**Expected**: 
- Scan request succeeds with 200 OK
- Source begins indexing process
- Toast shows "Scan queued" message

**Actual**: 
- Request returns 400 Bad Request
- No indexing occurs
- Error toast shows generic message

**Potential Causes**:
- Missing device_id validation in proxy route
- Ingest sidecar expects additional headers beyond X-API-Key
- Source ownership check failing
- Content-Type mismatch

**Debugging**:
```bash
# Check server logs for detailed 400 error
journalctl -u loseme-ingest-sidecar -f

# Check Next.js proxy logs
npm run dev
```

### 2. **Search: Message Clobbering on Session Switch**
**Status**: FIXED (but needs verification)
**Files**:
- `app/search/page.tsx` (loadConversation function)
- `components/search/ConversationSidebar.tsx` (onSelect handler)
- `lib/search-store.ts` (message state management)

**Description**:
When switching between conversations in the sidebar, the current conversation's messages were being overwritten by server data, causing loss of streaming responses and user messages.

**Expected**:
- Conversation history loads only when explicitly selected from sidebar
- Streaming responses continue uninterrupted
- Local optimistic messages are preserved

**Actual** (before fix):
- Automatic useEffect would overwrite messages on sessionId change
- Streaming responses could be interrupted
- User messages could disappear

**Fix Applied**:
- Removed automatic useEffect synchronization
- Added explicit loadConversation function
- Added SSE stream abort protection

**Verification Needed**:
- Test conversation switching during active streams
- Verify message persistence across tab changes

---

### 3. **Paperless: Source Scope Selections Not Saved**
**Status**: FIXED (but needs verification)
**Files**:
- `components/shared/SourceScopeEditor.tsx` (scope initialization)
- `hooks/usePaperlessSourceScope.ts` (scope management)
- `app/sources/page.tsx` (modal integration)

**Description**:
When editing Paperless source scope (tags, correspondents, document types), user selections were being lost due to the component re-initializing scope from props on every render.

**Expected**:
- User selections persist when interacting with dropdowns
- Selections are preserved when available items list updates
- Save button reflects actual changes made

**Actual** (before fix):
- Selections would reset when parent component re-rendered
- Available items list updates would overwrite user choices
- HasChanges() could return false even when user made selections

**Fix Applied**:
- Added useRef to track previous source ID
- Only initialize scope when source actually changes
- Prevent re-initialization on prop reference changes

**Verification Needed**:
- Test Paperless source scope editing
- Verify selections persist across interactions
- Test with multiple filter types

### 5. **API: Inconsistent Error Handling**
**Files**:
- `lib/api-client.ts` (global error handling)
- Various hook files (mutation error handling)
- `app/search/page.tsx` (search error handling)

**Description**:
Error handling is inconsistent across different API calls. Some show toasts, others show alerts, some fail silently.

**Expected**:
- Consistent error display (toasts for most errors)

- Error logging for debugging

**Actual**:
- Mixed use of toasts, alerts, and silent failures
- Some errors show raw HTTP status codes
- Limited error recovery options
